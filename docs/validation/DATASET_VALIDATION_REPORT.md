# Stage-0 新数据集校验报告

校验日期：2026-07-20
数据集：`output/damage_dataset.parquet`
规模：300,000 行 × 73 列
文件 SHA-256：`c49a63cdeea02012631fb233db663963b5034b4932a33aa680fa99a7b681ee98`

## 1. 总体结论

数据集的文件完整性、Stage-0 schema、坐标/运动学约束、样本唯一性、根谱系 split 隔离和序数标签一致性均通过。没有发现 NaN、Inf、重复可观测状态、跨 split 根家族或概率保序错误。

但该数据集目前不建议直接用于正式训练，并且现有 `nn_dataset.py` 的弱单元门禁会主动拒绝它。主要原因是：

1. 多个弹型—任务—等级单元缺少正样本或参考集样本，无法训练/校准独立弹型专家。
2. 主动爬行发生明显家族模式坍缩；部分“上千行正样本”只来自 2～11 个根家族。
3. 当前默认 Python 环境的 PyArrow 19 无法读取由 PyArrow 21 写出的文件。
4. 样本权重动态范围过大，且主动爬行后代继承父样本的 Phase-1 权重，统计含义不成立。
5. 3 次蒙特卡洛对部分高方差/阈值附近状态不足，且当前先平均规则事件再做非线性 OR。
6. 63.15% 的样本没有破片命中，但其中 M/F 毁伤率仍很高，需要额外验证冲击波标定。

## 3. 问题与修改方案

### P0-1：稀有/空单元使训练门禁失败

现有训练门禁要求：

- Small×C1：全表至少 2500，val/test 各至少 250；
- Small×M：val/test 的 L0/L1/L2 各至少 1500。

实际数据为：

- Small×C1：全表 1179，全部位于 train；val=0，test=0。
- Small×M：val=`2859/925/2029`，test=`2790/929/2067`，L1 均小于 1500。

因此即使换到兼容的 PyArrow 21 环境，`nn_dataset.py` 仍会抛出“v5 数据验收失败，拒绝开始训练”。

其他无法可靠学习或评估的单元包括：

| 单元 | train L2 | val L2 | test L2 |
|---|---:|---:|---:|
| Small×K | 0 | 0 | 0 |
| Small×C | 0 | 0 | 0 |
| Med-LM×K | 3 | 0 | 0 |
| Med-LM×C | 0 | 0 | 0 |
| Heavy×K | 1417 | 1 | 1 |
| Heavy×C | 2470 | 0 | 0 |

Med-RD×C2 的 val/test 也只有 24/20。当前网络默认使用四个独立弹型专家，这些空单元不能靠其他弹型的正样本自动补齐。

建议先由领域规则确认哪些单元属于“物理上不可达”：

- 若确实不可达，建立 `task_applicability[munition, task, level]` 掩码；训练时屏蔽对应损失，推理时固定输出 0，指标与阈值校准不再要求该单元有正样本。
- 若理论上可达，说明采样器没有覆盖该机制，需要调整弹型专属速度、距离、入射方位、起爆点和瞄准组件，而不是仅继续复制现有边界点。
- 保留当前自然分布 val/test，另外生成根种子完全独立的 `challenge_val/challenge_test` 数据集，用于稀有单元能力评估。不要把主动爬行后代塞入自然参考集。
- 门禁应同时报告自然参考指标和 challenge 指标；per-munition 阈值只在有足够校准样本时启用。

### P0-2：主动爬行家族模式坍缩

虽然根家族没有跨 split，但训练集内部的独立性严重不足：

- 最大根家族包含 3832 行，占全表 1.28%、全部爬行样本 6.13%。
- 556 个家族超过 10 行，190 个超过 100 行，1 个超过 1000 行。
- 最大家族全部为 Heavy/K2_HUNT，沿 11 级爬行链扩张。

稀有正类的家族集中程度更严重：

| 训练单元 | 行数 | 根家族数 | 最大家族占比 | 有效根家族数 |
|---|---:|---:|---:|---:|
| Small×C1 | 1179 | 11 | 40.1% | 4.0 |
| Heavy×K1 | 4560 | 291 | 32.9% | 7.9 |
| Heavy×K2 | 1417 | 3 | 58.1% | 2.0 |
| Heavy×C1 | 1902 | 935 | 39.3% | 6.2 |
| Heavy×C2 | 2470 | 2 | 94.2% | 1.1 |

这意味着 Heavy×C2 看似有 2470 条训练样本，实质上几乎只是同一个局部状态簇的重复扰动。代理网络很容易记住局部邻域，无法证明对新攻击几何有效。

建议：

1. 增加 `MAX_ROWS_PER_ROOT`，建议先取 64 或 128；最终裁剪和每一爬行阶段都执行。
2. top-off 配额从“目标行数”改为“目标独立根家族数 + 每家族最大行数”。
3. 每阶段选种前先对 `root_seed_id` 去重；同一根每阶段最多贡献固定数量的父样本。
4. 在标准化状态空间做 farthest-point、k-means 或分箱覆盖，不能只按距 0.5 的概率排序。
5. 训练采样器改为两级抽样：先均匀/加权选择根家族，再在家族内选择一个后代；或给每行乘 `1/family_size`/`1/sqrt(family_size)` 家族权重。
6. profile 与门禁新增 `unique_positive_roots`、`effective_positive_roots` 和 `largest_root_share`；建议稀有关键单元至少有 100～200 个独立根，最大单家族占比不超过 5%。

### P0-3：PyArrow 运行环境不兼容

文件元数据表明它由 `parquet-cpp-arrow 21.0.0` 写出。当前默认解释器是 Python 3.13.5 + PyArrow 19.0.0，读取任意列都会报：

```text
OSError: Repetition level histogram size mismatch
```

同一文件可由 `fastparquet 2026.3.0` 完整读取，且行数、字段、统计量和 SHA-256 正常，因此目前证据指向版本兼容问题，而非文件损坏。

建议：

- 按 `pyproject.toml` 新建隔离环境并使用 PyArrow 21+ 完成校验和训练；生成、验证、训练必须使用同一锁定环境。
- profile 增加 Python、NumPy、Pandas、PyArrow、代码版本和配置哈希。
- `validate_stage0_dataset.py` 在版本过低时输出明确的版本错误，或提供 fastparquet fallback。
- `_write_dataset_with_profile` 不应只回读 5 个关键字段，应使用兼容运行时逐 row-group、逐列或分批回读全部 73 列。
- 建议写出多个 row group，例如每 50,000 行一个，便于并行读取和局部诊断。

### P1-1：`loss_weight` 不稳定且语义混合

原始 `loss_weight` 范围为 `0.00037～2894.01`，中位数 18.57，p99 为 177.38：

- 10,491 行低于训练端下限 0.05；
- 2,376 行高于训练端上限 200；
- 原始权重有效样本量仅约 67,073；
- 经 `[0.05,200]` 裁剪后有效样本量约 129,767，仍只有总表的 43.3%。

生成端 Phase 1 先写入 `1/p_accept × physics_weight`，主动爬行后代通过 dataframe 复制继承父样本权重，但后代已经来自不同的 proposal/接受过程，该权重不再是它自己的有效 IPW。随后又叠加 CB 权重；训练端继续叠加平衡 batch、adaptive loss balance、per-munition pos_weight、focal loss 和任务权重。多种补偿可能重复纠偏。

建议：

- 拆分为 `aoa_ipw`、`active_sampling_weight`、`class_balance_weight`、`family_weight`，不再用一个列混合所有语义。
- 若无法计算主动采样 proposal density，爬行后代不要继承 Phase-1 IPW；可使用 1 或经过验证的 density-ratio 估计。
- 在采样时给接受概率设置下限，或使用 stabilized/normalized IPW、分弹型分位数裁剪、Pareto-smoothed IPW。
- 训练一次只保留一到两种主要不平衡机制，并通过消融选择；至少记录最终每个弹型×任务×等级的有效梯度质量。
- val/test 同时报告未加权指标和目标物理分布加权指标；不要仅依赖大权重的 validation loss 选模型。

### P1-2：蒙特卡洛重复及序数均值计算仍可改进

全表固定 3 次重复。高方差样本并非极少：

- K1 标准差 >0.20：10,438 行，其中 >0.40：7,546 行；
- C1 标准差 >0.20：11,755 行；
- F2 标准差 >0.20：6,792 行；
- M2 落在 0.45～0.55 附近：14,418 行。

当前代码先对每次仿真的 K1/K2 等规则事件求均值，再计算 `1-(1-p1)(1-p2)`。一般情况下：

```text
OR(mean(p1), mean(p2)) != mean(OR(p1, p2))
```

因此 K/M/F 的序数软标签没有包含每次重复中两个事件的协方差。

建议：

- 每个重复直接读取 `damage_tree.ordinal_probability_vector`，再对序数概率求均值和标准差。
- 对靠近 0.5 或标准差较大的状态自适应增加到 9～15 次，稳定区域保留 3 次。
- 若采用自适应重复，schema/profile 应允许逐行重复次数，并记录直方图；当前“全表重复次数必须一致”的门禁需要调整。
- 使用标准误差或置信区间作为训练置信权重，不应仅保存标准差而不消费。

### P1-3：无破片命中时 M/F 毁伤比例很高，需物理标定

189,453 行（63.15%）的 `total_hits=0`。这些样本仍有：

- M≥1：80.33%，M≥2：65.73%；
- F≥1：74.10%，F≥2：7.87%。

按弹型看，无命中样本的 M≥1/F≥1 为：

- Small：57.10% / 50.07%；
- Med-LM：87.79% / 83.88%；
- Heavy：97.63% / 89.84%。

这不构成逻辑错误，因为冲击波可以在没有破片命中时毁伤外部行走和观瞄部件；但它说明 M/F 标签主要可能由冲击波模型支配，也是 M/F 高正例率的来源。若冲击波阈值或遮蔽衰减偏激进，代理网络会忠实学习一个系统性偏差。

建议：

- 在固定状态子集上分别运行“仅破片”“仅冲击波”“两者联合”消融，统计每个任务的来源占比。
- 用试验数据、高保真有限元/水动力结果或公开标定曲线校核 Sadovsky 超压、装甲透射和部件阈值。
- 数据集中增加 `*_fragment_contribution`、`*_shock_contribution` 或至少机制标签，方便追踪代理模型学习的来源。
- 检查 0～5 m 采样域是否符合未来强化学习环境中的真实起爆距离分布；如果不是，应另建 deployment/reference distribution。

### P2-1：直接父节点谱系不完整

62,549 条爬行样本都有非空 `parent_id`，但其中 20,198 条（32.29%）的直接父节点已在最终裁剪中被删除。根谱系仍存在，因此 split 隔离不受影响；但无法从最终 Parquet 完整重建每一条爬行链。

建议在裁剪前单独写出 `lineage_edges.parquet(sample_id,parent_id,root_seed_id,stage,kept)`，或将 `parent_id` 指向最近的保留祖先并另存原始父节点。若不需要完整链，应把当前合同明确表述为“根谱系可追踪”，而不是“完整父子谱系可追踪”。

### P2-2：Logit adjustment 的物理先验仍有语义歧义

当前 adjustment 被明确 `enabled=false`，所以不会影响本次训练/部署，这是正确的。但 `PHYSICAL_PRIOR` 仍使用历史 `K1_prob/K2_prob` 命名，而 `pi_train` 已改成序数 `P(L≥1)/P(L≥2)`。K/M/F 的一级物理先验不能直接沿用旧事件 K1/M1/F1 比例。

建议：

- 输出键改为 `K_ge1_prob` 等显式名称。
- 若输入的是事件先验，先转换：K/M/F 的 ge1=`1-(1-p1)(1-p2)`，ge2=`p2`；C 保持嵌套语义。
- 最好从独立、非主动富化的 baseline/reference 数据估计先验及置信区间。
- 只有在偏移后的同一概率空间重新联合校准阈值后才能设为 `enabled=true`。

## 4. 建议的修复顺序

1. 先建立 PyArrow 21+ 的统一环境，否则现有校验器和训练入口无法读取数据。
2. 明确弹型—任务结构零掩码；决定哪些空单元应采样补齐，哪些应固定为不可达。
3. 修改主动爬行：按独立根家族计配额、限制每根行数、增加状态空间多样性。
4. 另建独立根的 rare-event challenge/calibration 集，解决自然 val/test 无法评估稀有单元的问题。
5. 重构权重列和训练不平衡机制，加入 family-balanced sampling。
6. 修正“逐重复序数概率后求均值”，并对高方差/近阈值样本增加重复。
7. 对冲击波主导的 M/F 标签做机制消融与物理标定。
8. 重新生成后再次运行本报告脚本；通过门禁后再开始正式训练。
